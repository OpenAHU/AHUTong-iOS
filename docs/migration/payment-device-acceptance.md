# iOS 支付功能实体机验收

本清单用于 iPhone 13 Pro 上的人工小额支付验证。所有步骤都必须使用本人获授权的校园账号和账户；不要录制、截图或分享姓名、学号、Token、Cookie、手机号、房间、余额、订单号、六位密码、安全键盘材料、签名或完整请求/响应。

推荐验收构建以本轮最终 GitHub Actions 记录为准。未签名 IPA 仍须在本机使用 Personal Team、Sideloadly 或 AltStore 做 7 天签名后安装，不能直接安装，也不等同于 TestFlight/App Store 包。

## 安全边界

- GitHub Actions、Simulator 和自动测试只使用 URLProtocol/Mock 合成响应；CI 设置应用级禁写开关并阻断真实支付域名，不创建真实订单、不自动扣款。
- PAY-01、PAY-02、PAY-03、PAY-05 已实现原生生产协议，本清单的最终扣款只能由测试者在真机上手动点击。
- 每条链路只使用学校允许的最小金额。点击最终确认后若出现超时、未知状态、App 退出或余额未及时变化，不得再次新建或重提；只使用页面上的“核验支付结果”或保留记录交由人工核验。
- 原始六位密码只应在原生安全输入框中输入一次。提交后输入框必须立即清空；任何日志、剪贴板、诊断页和恢复记录都不得出现密码或映射结果。
- 不要在 Debug 日志、Issue、截图或验收报告里粘贴完整 URL、请求字段、响应头、响应体或页面文本。

## 进入隐藏验收页

1. 打开“设置”。
2. 连续点击“安大通”App 信息卡片 8 次。
3. 进入隐藏 Debug 页面；普通设置列表中不应出现 Debug 选项。
4. “支付验收”只保留 PAY-04 招商银行扣款前 HEAD 验收；PAY-01、PAY-02、PAY-03、PAY-05 直接在各自生产页面人工验证。

## A. PAY-04 招商银行充值原生 HEAD 验收

1. 从隐藏 Debug 页进入“招商银行扣款前 HEAD 探测”。
2. 保持页面在前台，等待原生 HEAD 探测结束；此页面不会渲染校方网页。
3. 打开“查看并分享脱敏验收明细”。
4. 实体机通过必须同时满足：
   - 运行设备为物理 iPhone；
   - 一次性校园卡凭证已取得，但未显示或导出；
   - Cookie 仅在内存中按目标域、路径和 Secure 属性筛选，名称和值不会写入报告；
   - 每一跳都是无请求体 HEAD，且只到达受控校方 HTTPS 主机；
   - 最终到达校方扣款前路由；
   - 全程没有 WebView、JavaScript、资源加载、POST 或招商银行外跳。
5. 分享结果前再次确认文本中没有账号、Token、Cookie 值、金额、订单号和完整查询参数。

此项只证明“真实账号凭证 → 校方扣款前路由”的 HEAD 链路，不证明网页可交互、银行授权或真实扣款。

## B. PAY-01 校园卡充值

1. 打开“校园卡充值”，确认真实账户名称、卡类型和余额加载完成。
2. 支付宝路径：选择支付宝，确认只打开固定白名单小程序；App 不应向剪贴板写入姓名、学号、金额或凭据。是否继续支付由测试者在支付宝内决定。
3. 银行卡路径：回到 App，输入学校允许的最小金额并选择银行卡支付，只点击一次最终确认。
4. 成功时应显示同一订单成功并自动刷新校园卡余额；明确拒绝时应显示失败且允许重新开始新订单。
5. 若结果未知，只能核验原订单，不得重复点击创建第二单。

## C. PAY-02 浴室缴费

1. 打开“浴室缴费”，分别确认可用浴室映射到受支持的两个业务项；只对本人实际拥有账户的一项执行支付。
2. 输入本人获授权的 11 位手机号，核对现金余额与赠送余额。
3. 输入学校允许的最小金额和六位密码，只点击一次最终确认。
4. 页面应创建订单、完成安全键盘映射和最终提交；密码框应立即清空。
5. 成功时自动刷新同一浴室账户余额；拒绝或未知状态不得伪装成功，也不得自动创建第二单。

## D. PAY-03 电控缴费

1. 打开“电控缴费”，依次选择校区、楼栋、楼层和房间；改变上级时，下级选择必须清空并重新查询。
2. 选择本人获授权的房间，核对房间信息和余额。
3. 输入学校允许的最小金额和六位密码，只点击一次最终确认。
4. 页面应为当前订单获取独立的安全键盘材料并完成最终提交；密码框应立即清空。
5. 成功时自动刷新当前房间余额；拒绝、超时或未知状态不得自动重提或建单。

## E. PAY-05 网费充值

1. 打开“网费充值”，确认账户、套餐统计、快捷金额和服务端限额加载完成。
2. 选择学校允许的最小金额，输入六位密码，只点击一次最终确认。
3. 页面应完成入口预热、账户读取、创建订单、按订单获取安全键盘材料和最终提交；密码框应立即清空。
4. 成功时自动刷新网费账户；拒绝、超时或未知状态不得跳转学校网页，也不得自动重提或建单。

## 恢复与重复点击检查

这部分优先使用 Mock 自动测试验证；真机只观察自然发生的恢复，不要故意制造可能涉及资金的断网窗口。

1. 若已有 `orderCreated` 记录，重启 App 后必须显示“继续确认支付”，且继续时只能使用同一个 `orderid`。
2. 若最终请求可能已经发送，重启后必须显示“结果待确认”并只允许查询；不得再次显示可创建新订单的正常确认路径。
3. 连续快速点击确认只能触发一次流程；按钮进入进行中状态后不能重复提交。
4. 只有明确成功或明确拒绝才能解除待处理记录；未知结果必须保留。
