# iOS 支付功能实体机扣款前验收

本清单用于 iPhone 13 Pro 上的扣款前验证。所有步骤都应使用本人获授权的校园账号；不要录制、截图或分享账号、Token、Cookie、手机号、余额、订单号和支付密码。

## 安全边界

- “学校官方入口无扣款探测”只发送一次不带 Cookie、Token、账号、金额或请求体的 `HEAD` 请求，不登录、不创建订单、不扣款；它仍会暴露普通网络元数据，因此不称为匿名请求。
- “PAY-04 无扣款探测”不创建 WebView，不执行 JavaScript，也不加载图片、脚本或 iframe。原生临时会话只发送无请求体的 `HEAD`，关闭自动重定向并逐跳检查 `ycard.ahu.edu.cn` / `epay92.ahu.edu.cn` HTTPS 白名单；任何其他目标立即失败关闭。
- PAY-01、PAY-02、PAY-03、PAY-05 的本轮验收只覆盖账户查询、级联选择和官方入口。原生扣款仍由安全边界阻止，不得把“查询成功”记录成“支付成功”。
- 不要在 Debug 日志、Issue、截图或验收报告里粘贴完整 URL、响应头、响应体或页面文本。

## 进入隐藏验收页

1. 打开“设置”。
2. 连续点击“安大通”App 信息卡片 8 次。
3. 进入隐藏的 Debug 页面；普通设置列表中不应出现 Debug 选项。
4. 找到“支付验收”区域。

## A. 学校官方入口无凭据探测

1. 打开“学校官方入口无扣款探测”。
2. 点击“运行无扣款探测”。
3. 预期结果为“无凭据入口可达，未发起扣款请求”，并显示 HTTP `302`、目标主机 `ycard.ahu.edu.cn`。
4. 结果只能证明入口契约可达，不能证明账号登录、订单创建或扣款可用。

## B. PAY-04 招商银行充值原生 HEAD 探测

1. 从隐藏 Debug 页进入“招商银行扣款前 HEAD 探测”。
2. 保持页面不离开前台，等待原生 HEAD 探测结束；此页面不会渲染校方网页。
3. 打开“查看并分享脱敏验收明细”。
4. 实体机通过必须同时满足：
   - 运行设备为物理 iPhone；
   - 一次性校园卡凭证已取得，但未显示或导出；
   - Cookie 仅在内存中按目标域、路径和 Secure 属性筛选，名称和值不会写入报告；
   - 入口是 `https://ycard.ahu.edu.cn/berserker-base/redirect`；
   - 每一跳都是无请求体 HEAD，且只到达受控校方主机；
   - 最终到达校方 `/cashier-mobile/charge` 或 `/charge-app` 扣款前路由；
   - 全程没有 WebView、JavaScript、资源加载、POST 或招商银行外跳。
5. 分享结果前再次确认文本中没有账号、Token、Cookie 值、金额、订单号和完整查询参数。

此验收证明的范围是“真实账号凭证 → 校方扣款前路由”的 HEAD 链路，不证明网页可交互、银行授权或真实扣款；若学校不支持 HEAD，会安全失败，不能退回 WebView 脚本守卫冒充零扣款证据。

## C. PAY-01 校园卡充值只读验收

1. 打开“校园卡充值”。
2. 确认真实账户名称、卡类型和余额能加载；不得长期停留在占位符。
3. 输入合法金额并打开支付方式选择。
4. 支付宝入口只能使用固定白名单 URL，不应复制姓名、学号或任何身份字段到剪贴板。
5. 银行卡最终扣款仍应进入学校官方页面或显示安全阻断，不得在 App 内记为成功。

## D. PAY-02 浴室缴费只读验收

1. 打开“浴室缴费”，选择浴室。
2. 输入本人获授权的 11 位手机号。
3. 确认加载、查询成功、无账户和网络错误四种状态都有明确反馈。
4. 查询成功时核对现金余额与赠送余额；验收材料不得包含手机号或余额截图。
5. 不输入校园卡支付密码，不执行最终扣款。

## E. PAY-03 电控缴费只读验收

1. 打开“电控缴费”。
2. 依次选择校区、楼栋、楼层和房间；每次改变上级时，下级选择必须清空并重新查询。
3. 选择房间后确认显示房间信息和余额。
4. 分别验证空列表、请求失败和重试状态。
5. 不输入校园卡支付密码，不执行最终扣款。

## F. PAY-05 网费充值只读验收

1. 打开“网费充值”。
2. 确认账户、套餐统计、快捷金额和服务端限额能加载。
3. 输入边界金额，验证格式、两位小数和最大金额限制。
4. 最终充值只能进入学校官方页面；原生扣款必须继续安全阻断。
