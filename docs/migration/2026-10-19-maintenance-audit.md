## 首次登录与过期续期

用户反馈为“过一两天再打开后需要重新登录”，尚未获得该次真机错误明细。代码确认以下路径会扩大正常过期的影响：

1. 隐藏续期的 `inactive`、`timedOut`、`interactionRequired` 被映射为凭据不可用，并广播要求重新登录；根视图接收后清除快照。
2. 续期后业务接口再次报过期，就删除账号凭据；这不能证明密码错误。
3. CAS 任意可见错误横幅都被当作账号密码被拒绝，验证码和临时错误也会触发清理。
4. 首次登录校验后保存的是校验前 Cookie；普通教务读取后的 Cookie 轮换也没有统一持久化。

已修正：临时续期失败保留本地身份和凭据，最多自动重试一次；只有明确的账号密码拒绝才清理。冷启动使用原始会话校验，避免套用带自动重试的业务接口造成重复续期。首次登录及成功业务读取保存最新 Cookie，换账号不继承旧账号校园卡 Cookie；较早的续期结果在账号变化后不得直接写回旧身份。

验证包含四类临时失败、明确拒绝、连续过期、成绩与考试过期重试、首次校验轮换和换账号隔离。真实 CAS 页面及一两天后的持久登录仍须在本轮包上复验；使用 WebView 本身并不是已确认的根因。

## 真实成绩与考试查询

生产读取链为 Swift `RustCampusCoreAPI` → 固定 Rust SDK 的 `/grade`、`/grade/profiles`、`/grade/rank`、`/exam` → 校方教务页面/接口。入口使用真实数据源，未替换成演示数据。

本轮用 URLProtocol 在生产 API 层覆盖“首次过期 → 隐藏续期 → 同一只读请求重试 → 成绩/考试模型解码”，并验证账号隔离缓存。刷新失败时继续显示缓存，但新增明确提示；下次成功后清除提示。

没有授权校园账号，不能将这些契约测试表述为已查到真实成绩或考场。真机需核对成绩、GPA/排名、多学籍、考试时间/地点/座位，并观察一次过期恢复；反馈只需记录构建、设备、场景和结果，不提交凭据或完整个人数据。

## 通知方式与 APNs

- 课程提醒使用 `UNUserNotificationCenter` 和本地 `UNCalendarNotificationTrigger`，提前 10 分钟规划未来三周，最多保留 60 个课程请求；在进入前台和时区变化时维护。
- Live Activity 使用 `Activity.request(..., pushType: nil)`，没有远程更新令牌。
- 未发现 `registerForRemoteNotifications`、设备 token 注册/上传、远程通知回调、`aps-environment` entitlement 或 APNs provider；因此当前未接入 APNs。
- 本轮将提醒、Live Activity 和 Widget 的课程时间统一为校园时区，并按真实结束节次计算 Live Activity 结束时间，避免设备时区及跨午休偏差。

本轮范围是检查现状和修复既有本地行为。若未来需要教务公告主动推送，需单独确定公告源、provider、token 生命周期、签名能力和隐私说明；不能只添加一个 entitlement 就认定接入完成。参考 [Apple APNs 注册说明](https://developer.apple.com/documentation/usernotifications/registering-your-app-with-apns)。

## UI 与 UX 改进

本轮优化聚焦已经发现的使用障碍：成绩/考试缓存刷新失败有明确说明，临时认证错误不再把用户踢回首登，小组件添加指引区分安装包与共享数据问题，中/大组件保留周末课程列，组件预览使用不依赖账号的示例快照。页面结构继续沿用现有设计，不恢复教学评价或 Debug 入口。

全量 UI 回归还发现 iPhone 17 Pro 上浴室缴费的数字键盘可能遮住确认按钮，交互滑动未收起键盘。失败界面树确认金额已输入、账户已就绪，但键盘仍覆盖按钮。校园卡、浴室、电控和网费表单增加统一的键盘“完成”入口，回归用例通过该入口收起键盘后继续确认。

安全密码框重新获得焦点时可能清除旧输入；密码纠错用例因此明确清空并重新输入完整六位密码，不依赖原五位内容仍存在，继续验证位数错误、错误提示消失和最终成功。

课表日期 UI 用例另有测试状态隔离问题：前序用例开启了持久化的下学期预览，日期用例却按本学期锚点断言。已让该用例明确从本学期开始，保留产品对未知下学期日期显示占位的行为。

## 小组件缺失与重签安装

用户确认症状为“系统添加列表找不到安大通”，安装方式为下载 IPA 后重签。当前工程确实嵌入独立 Widget 扩展；尚未取得该设备重签后的包，因此不能断言扩展已被移除，也不能宣布 iOS 27 真机问题已修复。

排查优先级：重签后扩展是否仍存在 → 扩展签名及 Bundle ID 前缀是否有效 → 系统是否注册扩展 → 添加后是否能访问同一 App Group。Sideloadly 官方明确提供[移除扩展选项](https://sideloadly.io/)，AltStore 的[扩展会占用额外 App ID](https://faq.altstore.io/altstore-classic/app-ids)。两者都是排查依据，不是本设备的已证实根因。

已新增 `scripts/verify-widget-bundle.py`，并接入未签名 IPA 与 Archive 工作流，检查扩展、标识、版本和共享组；重签导出后可额外验证签名、entitlements 及存在的描述文件。App 与 Widget 共享组改为同一构建变量。运行时不再静默写入互不共享的私有目录；无法共享时明确提示安装方式问题。

本机工具链为 Xcode 27.0（27A266a），可用 iOS Simulator 运行时为 26.5；iOS 27 添加列表和重签后注册必须在用户设备上复验。
